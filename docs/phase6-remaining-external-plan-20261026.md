### 実行順と合否

1. 残存データの基準、今回のID一覧、署名受信経路、非秘密の記録、停止・終了担当を固定。Clockへ前進を要求する前に、前の変更結果とClock readyを照合。
2. Eを1周期更新。draft生成→原則1時間の確定猶予→paid、980円、同一契約ID、paid_through延長、実通知に対応するDB行を確認。通知確認前にGET billingを開かない。現在時刻を含むPlus・表示を確認。
3. Eを期間末予約。予約中はPlusを保持。直前の状態をDBと副作用のない権限RPCで保存し、当該期間末へClockを進める。実deleted通知→同じイベントIDのcommit→同じ契約canceled→Freeを確認。予約後の追加請求0を確認。
4. Fは初回成功後に失敗専用方法へ1回変更して更新。invoice.payment_failed、請求open、過去のpaid_throughを延長しない、Freeを確認。next_payment_attemptを根拠に上限内で進め、採用中の再試行終了動作を観測。hard decline・未設定予定・上限に達した場合は、終了動作の実証は未完了とし、設定を変えない。
5. 終了処理へ移る前に「通知試験終了」を記録。成功・失敗を問わず専用契約のみ安全に終える。終了処理の直接同期は別sourceにし、通知の合格を補わない。

非秘密の記録は、run/phase/単調増加seq、非秘密イベントIDと型、対象IDの照合結果、Stripe発生時刻、受信時刻、署名検証成否、HTTP結果、処理済みイベント行、DB commit後状態、権限、観測時刻、writer source。rawイベント・ヘッダー・URL・Customer本文・JWTを記録しない。受信プロセスが生きていてHTTP200というだけでは合格にしない。対象アプリ以外のwriterとGET billingによる同期を観測区間で止める。トランザクション内のイベント行と対象更新、直接更新の監査が揃わなければ相関未確認とする。新しい試験結果は過去Cの証拠にはしない。

## B. 実AIの費用承認案

**モデル候補は全経路 `gpt-6-luna` / Standard（service_tier=default）/ store=false、toolsなし。** 相談の既定値と一致する。診断はOPENAI_MODELが可変なので、今回の候補に明示固定して評価する案であり、現行公開設定を変更済みとはしない。他モデルへの自動切替なし。評価結果が不足なら追加費用を勝手に使わず、モデル変更案を別途提示する。

|---|---|---|
| 相談 外部01–14 | 既存14合成ケースを各1回。安全対応、否定・数値・訂正、別相手混入、圧力・操作的助言の回避、自然で実行可能な日本語。生成・修正文・安全判定を含む | **14×3=42回**、各入力12,000／出力2,400 token。再生成ボタンは使わない |

編集は最大3pass、1passのrewrite＋review、runAIの通信再試行最大1回も**80回枠内に数える**。全条件成立に80回以上必要ならそのケースは未完了。10ケースは1ラウンドであり、外部15–28の反復を合格へ換算しない。外部32の既存本文一括編集は行わない。

**最大842生成、入力24,504,000 token、出力6,900,800 token。** 2026-10-26の公式Standard短文料金は通常入力$0.10/M、出力$0.50/M。最も高い12h cache write $0.25/Mを全入力に仮定すると **$9.5764**、地域処理10%上乗せまで見て **$10.53404**。提案するモデル使用量の予約上限は **税別US$12**。税・為替・残高購入・自動補充は含まない。これは最大出力まで全呼出しが使う保守的試算であり、通常見積を保証しない。[公式料金](https://developers.openai.com/api/docs/pricing)、[Lunaのモデル・cache write・地域料金](https://developers.openai.com/api/docs/models/gpt-6-luna)。

DBは**ローカル隔離PGlite**に全migration・合成Auth・合成診断・合成の購入済み状態を用意し、既存C/Dや実本文を触らない。実プロンプト・スキーマ・pipeline/editorを使い、DB transportだけを隔離adapterへ向ける。旧liveテストの.env.local強制読込、既存ID／JSON再利用、全件backfillは禁止。専用 `scripts/phase6/ai-evaluation/provider.mjs` はSDKの計数→生成を包み、入力／出力上限・ケース別回数・最大費用の事前予約・Standard固定・結果不明停止・エラー非開示を実装済み。SDKそのものを合成HTTP応答へ接続して検証した。実プロバイダーへの接続は費用承認後にこの経路だけを使い、旧liveテストを直接起動しない。

費用承認前にできる計画・合成値の上限検証・既存pipeline/編集/再開の隔離回帰は再利用済み。追加の実AIは0回。人工の購入済みfixtureで実生成が成功しても、実購入→本番配信の成功とは別。本文の出力先は今回run専用のローカル評価成果物だけ、ログはcase/stage/token/cost/結果コードのみ。本人には安全・品質の最終評価、資格情報の保存・受渡し・失効など必要な箇所だけ依頼する。
