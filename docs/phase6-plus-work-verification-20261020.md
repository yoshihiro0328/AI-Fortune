# Plus / Portal 実行接続のローカル検証

実資格情報・実DB・実Stripeを使用しない検証。既存A/B、r5購入、ready本文、合成3行、過去の基準資料・完了済みSTEP 10は変更していない。外部33件は未検証のまま。

## 変更とレビューで修正した点

- 専用入口から固定10段階、実送信処理、暗号化記録、終了処理まで接続した。旧liveテストや任意コマンドは受け付けない。
- Workの正式ツールとの連絡を非秘密のローカル要求・応答に限定。同じ制御TTYを維持し、status確認前の試験進行を禁止。
- 実ブラウザー検証で、PostgRESTの単一行応答形式の転送漏れを発見して修正。許可するAccept値は2種類だけ。
- Portalでの期間末解約をアプリから重ねて実行する経路を実試験モードで拒否。
- 実通知成功の捕捉とDB同期を別々に確認し、画面GETが同期しただけでWebhook成功としない。
- 既知請求の回収停止を確認してから再試行設定を復元。設定2項目の復元・読み返しは独立して行う。
- 起動失敗時・アプリ停止失敗時も他プロセスの停止を続ける。停止失敗を成功に変換しない。
- 失効確認は3キーそれぞれを1回読み取り、401と無効コードを確認する。403・通信不明を失効済みとしない。
- 平文planと資格情報は独立して削除。暗号化済み監査と旧比較基準は保持する。

## 検証

資格情報を含まない作業コピーで、アプリ821テスト成功・外部33件スキップ、lint・型検査・本番ビルド成功。

Plusの移植可能な回帰テストは96件。内容は正常、権限拒否、応答不明、タイムアウト、中断、上限、本人JWTのRLS、設定復元、独立終了、失効確認、起動時後片付け失敗、アプリ停止失敗、受信済みキーの安全な結合を含む。ローカルの最終一括実行と、正式CIの同じテストで確認する。

Mac専用Chromeは実Nextアプリへ接続し、OSで外部通信を禁止する。ログイン→プラン→Checkout代替→アカウント→Portal代替・復帰を確認する。決済・Portal・Auth・請求エンジン・通知はローカル代替。実Stripe画面、実メール、実Webhook配送は検証済みとしない。

最終のMac連続実行は正常・画面操作失敗・入力切断・請求安全確認失敗の4件すべて成功（約126秒）。失敗ケースの「成功」は、停止と終了処理が期待どおり動き、未確認の復元を完了としないことを意味する。

実際の対話起動ではtty=true・login=true、同じ返却セッションを約624秒維持し、複数回のstatusでアプリ・合成CLI・中継の生存、10段階すべて、finishと正常終了を確認した。テスト実行器の子プロセスではTTYが失われるため、専用の対話テストは--test-isolation=noneを使用する。本番用の専用入口にはテスト実行器を挟まない。

短い合成タイムアウトによる途中停止も確認した。入力切断を無視する処理や、別セッションから同じ実試行を自動再開する処理は追加していない。

## CIとの区別

CIは移植可能なテストをloopback限定で実行する。Mac Chrome・OS隔離・実TTYはローカル証拠であり、Linux CIで実行済みとは記載しない。正式CIの結果は、pushしたコミットに紐づくActionsの完了結果で確認する。

実環境の設定復元は別文書の本人による保存・再表示の報告に基づく。今回の合成成功は、実設定を読み返した証拠ではない。MCPや正式APIの操作能力は、CI確認後に別途確認する。
