# 無料範囲での公開前準備 — 2026-10-07

テストURL: https://partner-mind-vdiordna-2059.vercel.app

独自ドメイン購入、有料SMTP、Stripe本番化、mainマージは行わない。検索公開は `PUBLIC_INDEXING_ENABLED=false`。標準ドメインのままMVPの受信テストは可能。ただし一般の利用者全員への認証メール配信は標準SMTPの対象外であり、正式な一般公開と区別する。

## 認証の確定設定

- Email provider / 新規登録 / Confirm email: ON。
- Secure email change: ON。Secure password change: 今回ON。
- 最低12文字、英大文字・小文字・数字・記号を必須に変更。アプリの新規登録・再設定も同一要件。既存ログインには新しい強度条件をかけない。
- Require current password when updating: OFFを維持。現在のアプリは、再設定リンクによる本人確認を経てパスワードを更新する。忘れた旧パスワードを必須にして復旧を壊さない。
- OTP有効期限3600秒、8桁。URLは登録用 `/auth/callback` と再設定用 `/auth/callback?next=recovery` の完全一致のみ。外部への任意リダイレクトは受け付けない。
- 漏えい検査はPro以上専用。警告は残る。無料の長さ・文字種の強化は漏えいデータベース照合の代わりにはならない。基準を満たす漏えい済みパスワードが必ず拒否されるとは言わない。有料化も外部パスワード送信も実施しない。
- custom SMTP: OFF。標準送信は組織メンバーのメール宛てのみ、現在2通/時（プロジェクト全体）。本番向けの到達保証はない。組織への招待を一般ユーザーの送信制限回避として使わない。
- 新規Freeプロジェクトは標準メール本文・件名の編集不可。デフォルト英語メールを保持。用意した日本語HTMLは将来custom SMTPへ移行する際に適用する。アプリの手続き画面は日本語。
- `AUTH_EMAIL_MODE=standard` を既定にし、登録画面にテスト参加者限定と英語メールの案内を表示。SMTP変更と受信確認後だけ `custom` に変更する。

根拠: [パスワード保護](https://supabase.com/docs/guides/auth/password-security)、[標準SMTPの制限](https://supabase.com/docs/guides/auth/auth-smtp)、[無料テンプレート変更制限](https://supabase.com/changelog/46599-changes-to-email-template-customisation-on-free-tier)。

## 本人の受信箱で行う最後の確認

パスワードをチャットに送る必要はない。Supabase「AI Fortune」の既存組織メンバーとして登録されている、自分が受信できるメールアドレスを使う。

1. [マイページ](https://partner-mind-vdiordna-2059.vercel.app/account)を開き「新規登録」。未登録のアドレスで自分のパスワードを設定する。
2. 確認メールの件名・送信元・リンク先を確認する。迷惑メールフォルダも見る。まずリンクを開かず60秒以上待ち、「確認メールを再送」を1回だけ使う。
3. 新しい方のメールの確認リンクを、登録を始めた同じブラウザで開く。日本語のマイページへ戻り、認証完了と診断保存を確認する。古い方のリンクは使わない。
4. ログアウトし、登録したパスワードでログインする。
5. 最初の送信から1時間以上待ち「パスワード再設定メールを送る」。2通/時はプロジェクト全体の枠なので、制限表示が出たらさらに時間を置く。連打しない。
6. 再設定メールのリンクを同じブラウザで開き、新しいパスワードを自分で設定する。更新後、旧パスワードが拒否され、新しいパスワードでログインできることを確認する。
7. 到着時刻・日本語の遷移・成功/失敗だけ報告する。メールリンク、確認コード、パスワードは共有しない。

すでに登録・認証済みの場合は登録し直さず、ログインと再設定を確認する。再送確認は未認証のテスト登録がある場合に実施する。HTTP成功・管理APIの生成リンクだけでは受信成功とはしない。

## お問い合わせの日常運用

専用画面: `/admin/contact`。メール認証済み運営担当者UUIDの `OPERATOR_USER_IDS` 指定が必要。未設定は全員拒否する。一般利用者を自動で管理者にしない。運営者本人のアカウント指定後に登録する。

指定前でも、既存のSupabase組織権限がある運営者はTable Editorの `contact_messages` で保存済み問い合わせを確認できる。アプリ管理画面と同じ status/admin_note/各日時を管理する。ほかの利用者にSupabase権限を付与しない。

- 毎営業日に「未対応」「対応中」を確認。古い受付から表示。返金、個人情報の削除、不正利用の訴えは優先して確認する。
- 着手時に「対応中」、内部メモへ確認事項・次の対応・担当者を記録。初回対応日時が残る。
- 運営者が普段の問い合わせ用メールから本人へ返信する。本文へ不要な診断内容や機微情報を転載しない。
- 実際に返信してから「別途返信したことを記録」を押す。この操作は送信しない。送信済みと受信到達は区別する。
- 解決後は「完了」。完了日時はメモ編集で上書きしない。再対応時は「対応中」へ戻し完了日時を解除する。誤送信・迷惑送信は迷惑送信に分類する。
- 受付番号で照合。利用者には「内容を確認のうえ対応します。受付メールはお送りしていません」と案内。自動メール未設定でもDB保存・対応・返信記録は動く。
- 正式な回答期限は運営者が入力するまで約束しない。返金・削除の本人確認と処理をメモで追跡する。

## 検索公開

テスト中は全体noindex、robots全拒否、空sitemap。正式公開を承認したときのみ `PUBLIC_INDEXING_ENABLED=true` にし再ビルドする。公開対象はTOP・問い合わせ・法務ページのみ。結果、有料レポート、アカウント、auth、診断フォーム、管理画面は引き続きnoindex。robotsでも非公開経路を除外する。noindexは認証の代わりではない。

canonical/OGPの基準は現在のVercel標準URL。将来URLを変える場合は `NEXT_PUBLIC_APP_URL`、Supabase Site/Redirect URLs、Stripe webhookとCheckout戻り先を同時に確認する。
