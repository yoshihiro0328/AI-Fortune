# 動的診断 v2

新しい診断だけが `question_flow_version=v2` を指定する。既存行とDBの既定値はv1のまま。旧10問のキー・文面・回答・完了結果は変換しない。

## 質問と保存

`diagnosis_questions` が質問候補の管理元。v2は共通9件、関係別42件、悩み別46件、最終確認4件、有料7件を初期登録する。候補数は表示数ではない。`is_active`、分類タグ、`phase`、`condition_json`、`priority`、`max_uses`、`followup_group` で管理する。

- 共通回答からAIが関係タイプ・悩みタイプと必要な候補キーを選ぶ。
- サーバーは有効な候補、分類、条件、回答済みテーマ、重複グループ、上限を再検証する。
- 通常は共通9＋関係4＋悩み3を目安とし、具体的な記述があれば減らす。分岐追加は最大9、最終確認は最大3、無料全体は22以下。
- 最終確認は情報不足・矛盾が結果を左右する場合だけ。候補で補えない点のみ自由生成し、既存の日本語編集・安全レビューと重複レビューを通す。
- 質問の選択理由はサーバーだけに保存し、公開レスポンスでは明示的に除去する。

`diagnosis_selected_questions` に文面・選択肢のスナップショット、順序、理由、表示時刻、回答時刻と回答を保存する。`diagnosis_answers` も引き続き利用する。選択と回答の保存はそれぞれDBトランザクション。再読込は保存済みの構成を使い、AIで選び直さない。

「戻る」で共通回答を実際に変更した場合だけ、後続質問を無効化して選び直す。関係・悩みの回答を変更した場合は最終確認だけを無効化する。無効化した回答は分析入力から外す。完了後の回答は変更できない。

## 有料・安全

Sandboxの決済確認後、生成前に有料質問が必要かAIが判定する。0〜5問。質問待ちは `paid_reports.status=awaiting_answers` として定期再試行から除外する。回答後にqueuedへ戻す。DBのclaim処理もv2の質問完了を確認するので、古いワーカーが質問を飛ばして生成することはできない。

危険を示す回答は、その時点で既存の文脈付き安全判定へ送る。高リスクなら質問・有料生成を停止し安全画面へ移す。否定表現は既存のルールを保持する。通常の分析時と有料質問選択時にも安全判定を行う。

すべてのAI工程へ、共通・関係・悩み・最終確認・有料追加の回答を分けて渡す。自由生成した質問の理由は分析対象の本人発言には混ぜない。

## 運用

質問履歴はRLS有効・anon/authenticatedの権限なし。所有権を検証するサーバーAPIだけが利用する。新しいRPCはservice_roleだけ実行可能。公開の旧質問一覧はv1に限定し、古いアプリが並存しても10問のまま動く。v2候補のrequired=falseは旧ワーカーの全質問必須判定への互換措置で、v2は選択された質問の回答有無で完了を判断する。

イベントはdynamic_question_selected/viewed/answered、diagnosis_abandoned/completed、paid_followup_started/completed。離脱イベントはページ非表示時の候補イベントであり、確定離脱数は再開・完了と突き合わせて集計する。

## 検証

- `npm run lint` / `npm run typecheck` / `npm test` / `npm run build`
- `tests/dynamic-database.sql` は必ずbegin/rollback内で実行。
- `scripts/dynamic-e2e.mjs` は合成相談を実API・実AIで実行する。`TEST_BASE_URL` と必要な接続設定を用意。API利用料が発生する。Cookieを含む作業記録は `../../work/dynamic-e2e` のみに保存し、Gitへ追加しない。
- `scripts/dynamic-paid-e2e.mjs` は上記の合成診断だけにテスト用の決済済み行を作る。実際のStripe決済試験とは区別する。
- `scripts/dynamic-v1-compare.mjs` は新しい合成v1診断を作り、既存データを変更せず比較する。

Production・main・実決済・検索公開の設定はこの変更に含まない。
