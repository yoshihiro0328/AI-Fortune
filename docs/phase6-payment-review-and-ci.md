# 単発購入と閲覧検証のレビューとCI

単発980 JPYのSandbox購入、その後の合成本文設定、Aの閲覧成功・Bと未ログインの本文拒否・本人JWTのRLS確認は完了済み。本変更は、そのコードと回帰テストを作業ブランチへ確定するもの。実購入、ログイン、本文設定、STEP 10の実DB検証は繰り返さない。合成本文はAI生成の成功を意味しない。

## コードの範囲

- アプリ：既存Checkoutの購入・診断紐付けとWebhookのAccountを照合。専用ローカル環境では対象診断・購入者を固定し、AI生成を拒否する。通常の認証・所有権・Webhook署名・DB権限を緩めない。
- `payment-runtime`：初回購入専用。通信許可、各送信の上限、原manifestの再利用、TTY制御、価格無効化・専用プロセス停止・一時情報削除を扱う。キー失効は本人のDashboard操作と別確認が必要。既存の購入を持つDBでは事前照合で停止する。
- `payment-continuation`：購入済みqueuedレポート1件の本文設定用。既に本文がreadyの現状には再実行しない。
- `payment-verification`：readyレポートの閲覧確認専用。psql・DBパスワード・本文変更・Stripeは不要。診断一覧と対象本文への通信のみを許可する。ページの不要な相談概要・生成再試行・分析イベント送信を専用フラグで止め、通常画面の既定動作は維持する。
- 保護された入力はリポジトリ外から明示指定する。コードのimportやCIでは実行入力・資格情報を探索しない。

## 今回のレビュー修正

1. 起動テストの実OSアプリ起動を、CI用の子プロセス代替とMac用の実アプリ検証に分離した。失敗ケースの削除・skip化はしていない。
2. 購入・継続・閲覧中継は、不許可要求・上流障害・不正応答を受けた直後に自ら停止状態へ移り、後続要求を上流へ送らない。
3. エラーが英大文字だけでも無条件でログへ出さず、明示的な許可コードのみ保存する。レスポンス本文・Cookie・JWT・パスワードを記録しない。
4. 閲覧専用ランチャーの正常完了・入力切断・事前不一致・確認失敗について、暗号化保存、終了コード、子プロセス停止、一時情報削除、本文不変を回帰検証する。

## CIで実行する検証

`npm run test:payment-scripts` はNodeの回帰テスト3群を直列実行する。17件のmigrationを適用したPGliteで、実際の起動前クエリー、metadata内のdiagnosis_id、本文SQLの限定更新とrollback、購入済み状態、本人ロールによるRLSを確認する。通信・CLI・psqlプロトコルの試験には合成応答や専用の模擬実行ファイルを使い、実サービスへ接続しない。

専用CIガードは実資格情報の環境変数と実.envファイルを拒否し、通常fetchの外部宛て通信を拒否する。これはMacのOS通信隔離そのものの代用ではない。Ubuntu CIには資格情報を登録せず、既存外部33件の有効化フラグもOFFに固定する。

既存のVitest、lint、型チェック、Next.jsビルド、Dockerの完成SQL・所有権・HTTP・Stripe初期化隔離検証も維持する。GitHubの対象コミットに対するCI成功を正式な結果とし、別コピーでの成功だけでは確定しない。

## Macでのみ実施する検証

`payment-runtime/offline-http.mjs`、`offline-control.mjs`、`payment-verification/offline.mjs` はMacのsandbox-exec、既存Chrome、対話TTYを使用する。ブラウザーを使う場合も合成Authと隔離DBのみ。対話起動はtty・loginを有効にした同じ制御セッションを終了まで保持する。

Ubuntuの子プロセス・ブラウザー代替による成功を、実画面操作やOS迂回拒否の成功とは数えない。過去に合格したMac検証と実サービスでの画面操作は保存済み記録として維持する。変更した安全制御については今回の回帰テストで再確認し、実購入を繰り返さない。

## 記録と未検証の範囲

Gitへ含めるのはコード、合成fixture、テスト、整理済みの文書のみ。review-evidence、元manifest、暗号化バックアップ、復号キー、Cookie、Authユーザー情報、試行予約、生の運用ログは公開しない。旧記録はローカルに保持する。

完了済み実検証では、比較対象14テーブルが不変、利用制限は32行のうち許可された5行のみ更新、追加購入・AI生成なし、専用環境の終了と一時資格情報削除を確認済み。Authシステムテーブル全体が不変とした記録ではない。

外部33件は[分類表](phase6-external-test-matrix.md)の最新節を参照。月額Plus/Portal、実AI生成、公開環境での配送・運用、Production公開判定は今回の完了に含めない。mainマージ・デプロイも実施しない。

## CIイメージ取得制限への対応

CI `39378731945` と `39379317832` は、アプリとスクリプトの検証後にECR Publicの `registry_rate_limit`（コンテナー開始の終了コード125）で失敗した。これらをCI全体の成功とは扱わない。

[Supabase公式の配信定義](https://github.com/supabase/postgres/blob/develop/.github/workflows/mirror.yml)では、Docker Hubの `supabase/postgres` をECR Publicへミラーしている。2026年10月20日に両者の `17.11.0.004` の公開マニフェストが完全一致することを確認した。Ubuntu CIは同じlinux/amd64イメージをDocker Hubからdigest指定で取得し、既存の検証用ローカルタグを付ける。SQL、migration、試験項目、実サービス接続先は変更しない。

固定digest：`sha256:e85bc10ac5b141223b289e1e8dc8d448cf3df92501917149db0366b9c5aaf053`。取得またはOS/architecture照合に失敗したらCIを失敗させ、テストを省略して成功扱いにしない。追加のサービス資格情報・契約は使用しない。
